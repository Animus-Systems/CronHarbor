# CronHarbor operator dashboard

Vue 3 + TypeScript static client for the optional CronHarbor API. The Rust daemon remains the policy and execution authority. No Node production server is required.

```sh
npm ci
npm run typecheck
npm test
npm run build
```

Serve `dist/` with CronHarbor's full profile or an HTTPS static host. The client uses hash routes, so deep links work without server-side route rewriting. Development: `npm run dev` starts on loopback and proxies `/api` to `http://127.0.0.1:8090`. Set `CRONHARBOR_API_URL` for another development proxy target.

The default browser API is same-origin `/api/v1`. An operator-controlled `config.json` beside `index.html` may contain `{"apiBaseUrl":"https://scheduler.example.com/api/v1"}`. Non-loopback HTTP, URL credentials, query strings and fragments are rejected. Cross-origin deployments also require the API's explicit CORS allowlist.

CronHarbor hosting reads this regular, nonsymlink configuration file at startup (maximum 64 KiB) and adds only the configured origin to CSP `connect-src`. Use an explicit absolute URL for a remote API; scheme-relative URLs are rejected. Invalid configuration fails closed. Restart the HTTP host after changing the file so its policy and browser configuration agree.

Bearer tokens are entered as passwords, kept in tab memory, sent only in Authorization headers and cleared on disconnect/reload. Logs and diagnostic payloads are rendered as text. Mutations use fresh idempotency keys; an ambiguous submission retains its exact intent for an explicit manual retry. Accepted operations are queried by their durable IDs without automatically resubmitting mutations.

Response models in `src/generated/contracts.ts` are generated by the repository's Rust `export-types` command. Change `src/contracts.rs` and regenerate instead of editing generated declarations. Runtime guards reject unsupported payloads. Workload lists are summaries; detail requests fetch definitions and probe history.

The console covers workload validation and revision-CAS apply, source-owned read-only definitions, job scheduling previews, service controls, execution evidence/reconciliation, bounded virtualized logs, durable operations, adapter observations, token metadata/creation/revocation and audit pagination. Installation log retention is available through Settings or the trusted `log-storage` CLI. Backups, restore reconciliation, executor allowlists and global dispatch administration use deployment configuration and the trusted CLI.

Execution detail shows the latest attempt's outcome separately from its queued retry. A failed attempt with a pending retry remains cancellable. Diagnostics recover through bounded polling or Refresh after a transient error; cancelling the retry preserves the failed attempt in history.

## Browser verification

Install Chromium once with `npx playwright install chromium`. From the repository root, use `python3 scripts/test_full.py --browser` for disposable daemon/API journeys, synthetic UI fixtures and the separate-origin scenario. Use `python3 scripts/test_log_rotation.py --browser` for the specialized owner-restart/frozen-log fixture. Build Full and the dashboard first as described in [the runbook](../../docs/RUNBOOK.md).

For a manually provisioned disposable fixture, run `npm run e2e` from this directory. The suite contains isolated synthetic 1,000-workload/10,000-line fixtures and real API journeys. Supply scoped fixture credentials and the Python executable used for the producer:

```sh
CRONHARBOR_DASHBOARD_URL=http://127.0.0.1:8090 \
CRONHARBOR_E2E_TOKEN_FILE=/path/to/admin.token \
CRONHARBOR_E2E_VIEWER_TOKEN_FILE=/path/to/viewer.token \
CRONHARBOR_E2E_FILE_WORKLOAD=existing-file-owned-workload-id \
CRONHARBOR_E2E_PYTHON="$(command -v python3)" \
npm run e2e
```

Use a disposable local instance: real tests create jobs, a service and an expiring viewer token, run jobs, stop the service and revoke the created token. Missing fixture credentials skip their real journeys; the separate-origin and owner-restart/freeze cases need the specialized fixtures supplied by the scripts above. A plain e2e run does not prove those cases passed. Test traces are disabled to avoid retaining bearer headers or token-entry values. Screenshots and the HTML report are ignored build artifacts under `test-results/` and `playwright-report/`. Browser assertions exercise responsive layouts and keyboard controls; they do not establish a WCAG compliance certification.
